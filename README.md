# Inception-of-Things

Инструкции по запуску и показу практических пунктов eval sheet:

- [p1: две VM, K3s server и worker](p1/README.md#проверка-на-защите-команды-по-eval-sheet).
- [p2: три приложения, реплики, Ingress, curl и браузер](p2/README.md#проверка-на-защите-команды-по-eval-sheet).
- [p3: K3d и Argo CD](p3/README.md).
- [bonus: локальный GitLab](bonus/README.md).

p1 и p2 проверены запуском на Linux x86_64 с Vagrant и VirtualBox.
Теоретические вопросы и объяснение конфигурации входят в защиту отдельно.

## Как пользоваться командами

**Хост** — твой обычный терминал `dogadinm@arch-laptop`.
**VM** — терминал после успешного `vagrant ssh`, с приглашением
`[vagrant@mdogadinS ~]$` или `[vagrant@mdogadinSW ~]$`.
После команды SSH сначала дождись приглашения VM, затем вводи её команды.
`exit` возвращает на хост. Vagrant запускай без `sudo`.

## Порядок запуска p1 → p2

Команды на хосте из корня репозитория. Если p2 уже запущена, сначала
останови её командой `vagrant halt` в каталоге `p2`.

```sh
cd p1
bash scripts/up.sh
```

Скрипт запускает обе VM и проверяет SSH, IP и два узла Ready.
Далее выполни [сценарий показа p1](p1/README.md#проверка-на-защите-команды-по-eval-sheet).

После показа p1 останови обе VM и запусти p2:

```sh
vagrant halt
cd ../p2
bash scripts/up.sh
```

Скрипт проверяет узел, три приложения, три реплики app2 и HTTP-маршруты.
Далее выполни [сценарий показа p2](p2/README.md#проверка-на-защите-команды-по-eval-sheet).

**Одновременно p1 и p2 не запускай:** они используют IP `192.168.56.110`.
Первый запуск скачивает образ, пакеты и контейнеры и занимает больше времени.

## Быстрая повторная проверка

Из каталога запущенной части:

```sh
bash scripts/check.sh
```

Для входа на сервер:

```sh
vagrant ssh mdogadinS
```

Если вход завис, нажми `Ctrl+C` и смотри
[восстановление SSH](p2/README.md#если-ssh-зависает).
Для p1 команды восстановления выполняются в `p1`; `vagrant reload`
без имени перезапускает обе VM этой части.
